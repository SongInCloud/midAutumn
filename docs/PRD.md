# 中秋文化介绍网站产品需求文档（PRD）

| 项目 | 内容 |

| 版本 | v1.0 Draft |
| 日期 | 2026-08-24 |
| 形态 | React 单页文化展示网站 |
| 定位 | 面向大众的中秋文化数字展览 |

## 1. 项目背景

此前七夕项目采用了带有起点、推进过程与终点的线性体验。本次中秋网站不延续该模式，而是建设一个以中秋文化介绍为核心的开放式内容网站。

用户进入后无需完成任务、解锁章节或按固定顺序浏览。首页直接呈现中秋氛围和主要内容入口，用户根据兴趣自由探索。动效与互动用于增强文化内容的表现力，不构成闯关、收集、积分或剧情推进机制。

## 2. 产品目标

### 2.1 核心目标

1. 系统介绍中秋节的历史、习俗、传说、诗词、美食与文化意象。
2. 建立具有鲜明中式审美和中秋辨识度的沉浸式浏览体验。
3. 通过丰富但克制的动效，让内容更生动、更容易理解和记忆。
4. 支持非线性浏览，任何核心内容都可以从首页或导航直接到达。
5. 在桌面端和移动端均保持良好的视觉效果与可读性。

### 2.2 非目标

- 不设计线性故事、关卡、步骤引导或强制浏览顺序。
- 不设置月华、积分、成就、签到等收集或成长系统。
- 不要求完成灯谜、小游戏后才能查看内容。
- 不建设账号、评论、社区或内容管理后台。
- 不制作营销页、电商页或个人情感纪念页。
- 不延续七夕项目的页面结构、交互流程或视觉模板。

## 3. 产品定位与用户

### 3.1 产品定义

一个可自由漫游的中秋文化线上展馆。网站以“同一轮月亮下的中秋文化”为内容主轴，通过主题导航、模块化内容和局部互动，让用户自由阅读、观看与探索。

### 3.2 目标用户

- 对传统节日和中国文化感兴趣的普通用户。
- 希望快速了解中秋文化的年轻用户。
- 中秋期间寻找节日氛围内容的移动端访客。
- 需要基础中秋文化素材的学生、教师或内容创作者。

### 3.3 典型场景

- 用户从分享链接进入，随意浏览感兴趣的内容。
- 用户想了解某项习俗或典故，通过导航直接定位。
- 用户在移动端碎片化阅读诗词、习俗或月相知识。
- 用户因视觉或动态效果停留，并进一步了解中秋文化。

## 4. 核心体验原则

### 4.1 非线性浏览

所有主要模块地位平行，不存在“第一关”“下一章”“完成进度”。用户可以通过导航、目录或锚点直接访问任意主题。自然向下滚动只是浏览方式，不代表叙事流程。

### 4.2 内容优先

每个视觉元素和互动必须服务于文化理解、氛围营造、信息层级或浏览反馈。不为“可玩性”加入与介绍内容无关的积分、收集或挑战。

### 4.3 动静有度

首屏可有较强视觉冲击力；正文区域降低持续动画密度，确保阅读舒适。避免所有中秋元素同时移动。

### 4.4 中式设计而非元素贴图

中式风格通过版式、色彩、留白、字体、纹样、材质和运动节奏共同建立。月亮、桂花、灯笼、玉兔、祥云、山水等元素分区使用，不能无序堆放。

## 5. 信息架构

网站采用单页多主题结构：

- 中秋概览：何谓中秋
- 节日溯源：千年流变
- 人间风俗：各地共此时
- 月下传说：神话与想象
- 风雅诗词：月照古今
- 舌尖中秋：一口团圆
- 共赏明月：月亮知识

导航持续提供当前位置反馈。桌面端使用横向导航，移动端使用折叠菜单或主题抽屉。

## 6. 页面模块需求

### 6.1 全局导航

- 展示网站名称及七个主题入口。
- 点击主题平滑定位到对应模块。
- 当前可视模块高亮。
- 支持锚点直接访问指定模块。
- 离开首屏后显示返回顶部入口。
- 音效开关仅在实际提供声音时显示。
- 不显示浏览进度、任务进度或解锁状态。

### 6.2 首屏：一轮明月

目标是在数秒内建立中秋主题、文化气质和内容定位，并展示主要内容入口。

内容包括核心标题、文化展览导语、月亮与山水等主视觉，以及历史、习俗、传说、诗词、美食入口。

互动要求：

- 鼠标或设备姿态可引起轻微月光、云层或景深变化。
- 点击月亮可展示简短月相知识，不产生积分或收集反馈。
- 首屏元素分层进入，动画结束后保持安静稳定。
- 用户可直接选择主题，不需要先点击“开始旅程”。

### 6.3 中秋概览：何谓中秋

介绍节日时间与名称来源、团圆与丰收等文化含义、发展脉络和现代意义。采用关键词、信息卡或可展开知识点，任何内容均可独立打开。

### 6.4 节日溯源：千年流变

介绍先秦月亮崇拜与秋夕祭月、唐代赏月风尚、宋代节俗成熟、明清团圆寓意强化及当代传承。

采用可拖动时间轴、年代浮层或卷轴排版。任一时代可直接展开，切换可使用水墨晕染、纸张展开或印章落款转场。

### 6.5 人间风俗：各地共此时

介绍赏月、祭月、拜月、吃月饼、饮桂花酒、赏桂、玩花灯、舞火龙，并补充至少三至五项地域特色习俗。

采用可筛选卡片或地域分布图，支持按“饮食”“礼仪”“游艺”“地域”查看。灯谜仅作为习俗示例或轻量互动，不构成闯关。

### 6.6 月下传说：神话与想象

介绍嫦娥奔月、玉兔捣药、吴刚伐桂、月宫与蟾宫意象。每个传说为独立入口，可任意选择。

点击角色或场景热点查看人物简介、故事版本和文化寓意。明确区分传说与历史事实。

### 6.7 风雅诗词：月照古今

收录中秋或明月主题代表性诗词，展示作者、朝代、原文和简短赏析，支持按“团圆”“思乡”“怀人”“赏月”筛选。

诗词可使用卡片、卷轴或书页形式切换。朗读为可选功能，只能由用户主动开启。

### 6.8 舌尖中秋：一口团圆

介绍月饼的来源与寓意、主要流派，以及桂花酒、柚子、芋头、螃蟹等节令饮食和地域差异。

点击月饼剖面可查看馅料和流派信息。食物卡片可筛选或轮播，但不加入制作任务、配方合成或经营玩法。

### 6.9 共赏明月：月亮知识

介绍月相原理、中秋月亮是否一定最圆、月升与赏月常识及古代月相称呼。

用户可拖动控制器观察月相变化，系统同步显示名称和说明。互动结果是知识反馈，不产生得分、成就或完成状态。

### 6.10 页尾

包含中秋祝语、内容来源、参考资料、项目信息、版权说明及返回顶部入口。

## 7. 交互需求

### 7.1 首期必须具备

- 锚点导航与当前模块高亮。
- 文化卡片展开与收起。
- 主题筛选或标签切换。
- 传说角色或场景热点查看。
- 诗词内容自由切换。
- 月相拖动观察。
- 桌面端悬停反馈与移动端触控反馈。

### 7.2 可选增强

- 环境声音与诗词朗读。
- 轻微鼠标视差。
- 生成中秋诗句分享卡片。
- 根据本地时间显示不同月色或问候语。

### 7.3 禁止或避免

- 必须点击“开始”后才能访问内容。
- 完成前一模块后才能打开后一模块。
- 收集月光、积分、碎片或道具。
- 任务清单、完成百分比、关卡提示。
- 自动播放且无法关闭的声音。
- 高频闪烁或影响阅读的持续动画。
- 必要信息只能通过悬停访问。

## 8. 视觉设计要求

设计关键词：东方、静谧、丰盈、雅致、月色、团圆、当代中式。

色彩建议：

- 主背景：黛蓝、鸦青、墨黑等夜景色。
- 主强调：月白、桂花金、暖米色。
- 辅助强调：朱砂、赭石、松石绿。
- 正文可使用宣纸白或低饱和浅色背景，形成明暗节奏。

元素与排版：

- 核心元素：月亮、月相、山水、桂花、祥云。
- 辅助元素：玉兔、灯笼、窗棂、印章、折扇、古建筑剪影。
- 装饰元素分区使用，避免同屏堆满全部符号。
- 优先使用原创插画、SVG、CSS 图形或授权明确的素材。
- 标题可使用书法气质字体，正文必须清晰易读。
- 竖排文字只用于短标题或装饰。
- 英文装饰文字不能压过中文主体内容。

## 9. 动效设计要求

1. 环境动效：云层、月光、桂花缓慢运动。
2. 入场动效：模块进入视口时一次性渐入或展开。
3. 反馈动效：悬停、点击、切换时提供短暂明确响应。
4. 内容动效：时间轴、月相随用户操作实时变化。

约束：

- 优先使用 transform 和 opacity。
- 非关键动画离开视口后暂停。
- 支持 prefers-reduced-motion，关闭视差与大幅转场。
- 不使用快速闪烁效果。
- 主要内容不依赖动画结束后才可访问。

## 10. 响应式要求

- 桌面端适配 1280px 至 1920px，控制正文最大宽度。
- 平板端多列布局收缩为双列或单列，减少复杂视差。
- 移动端以单列为主，导航使用折叠菜单或主题抽屉。
- 交互热区不小于 44×44px。
- 必要信息不依赖 hover。
- 移动端减少装饰层，长时间轴改为横向滑动卡片或列表。

## 11. 内容要求

- 历史信息、节俗来源、诗词作者及原文必须核对。
- 多版本传说使用“相传”“其中一种说法”等表达。
- 使用通俗但准确的中文，避免过度学术化。
- 每个模块包含标题、导语和可独立理解的正文。
- 图片、字体、音频等素材必须确认版权或许可。
- 引用和参考资料在页尾集中说明。

## 12. 非功能需求

### 12.1 性能

- 首屏优先加载关键文字和主视觉骨架。
- 图片使用 WebP 或 AVIF，并按实际尺寸提供资源。
- 非首屏插画、音频和复杂组件懒加载。
- 避免大量粒子、滤镜或动画造成持续高资源占用。
- React 生产构建不出现阻断性错误。

### 12.2 可访问性

- 所有可操作元素可通过键盘访问，焦点清晰可见。
- 图片和重要插画提供替代文本。
- 正文与背景具有合理对比度。
- 图标按钮具有辅助说明。
- 音频默认关闭，并提供暂停与静音控制。

### 12.3 兼容性与 SEO

- 支持最新版 Chrome、Edge、Firefox、Safari 及常见移动浏览器。
- 不支持高级动画时，内容仍可正常阅读和导航。
- 页面具有准确标题、描述和语义化标题层级。
- 核心内容存在于可索引 HTML 中，不只绘制在 Canvas 内。
- 提供适合社交分享的封面、标题和描述。

## 13. 版本范围

### P0：首期必须完成

- 全局主题导航和非线性浏览结构。
- 七个核心文化主题的真实内容。
- 中式视觉系统与桌面、移动端适配。
- 内容展开、筛选、切换、月相观察等互动。
- 基础环境、入场和反馈动效。
- 减少动态效果、键盘操作和基础无障碍。
- 内容来源与版权说明。

### P1：时间允许时完成

- 诗词朗读与环境声音。
- 地域习俗可视化地图。
- 诗句分享卡片。
- 更精细的插画热点和微交互。

### P2：后续迭代

- 多语言版本。
- 独立内容管理后台。
- 向其他传统节日扩展。

## 14. 验收标准

1. 无需前置操作即可查看主要内容和主题入口。
2. 可从导航直接访问任意核心模块，不受浏览顺序限制。
3. 不存在积分、收集、解锁、关卡和完成进度等线性机制。
4. 七个核心主题均有真实文本内容。
5. 至少提供四类与内容直接相关的互动。
6. 桌面端和移动端均可完整访问所有必要内容与操作。
7. 必要信息不依赖悬停、动画或声音才能获得。
8. 开启减少动态效果后，视差和大范围动画被关闭或弱化。
9. 主要操作支持键盘，并具有可见焦点。
10. 不复用七夕项目的线性叙事、情感书信或星河收集框架。
11. 文化内容具有参考来源，素材版权状态明确。
12. React 项目可完成生产构建，无阻断使用的控制台错误。

## 15. 待确认事项

1. 产品最终名称。
2. 内容深度偏大众科普、青少年教育还是文学性展览。
3. 是否加入地域习俗地图及覆盖范围。
4. 是否需要诗词朗读和环境音乐。
5. 首期是否包含分享卡片。
6. 视觉风格偏工笔、剪纸、水墨、宋式美学还是当代国潮。
7. 是否需要部署到公开域名及上线日期。

## 16. 方向总结

本项目的“可玩性”来自对内容的自由探索、视觉反馈和知识互动，而不是任务与奖励系统。网站应像一座开放的中秋文化展馆：入口清晰、主题平行、内容充实，用户既可以快速浏览，也可以在任意感兴趣的主题中停留。

后续设计与开发应持续验证三个问题：页面是否仍可自由跳转、互动是否帮助理解内容、视觉效果是否影响阅读。如果任一答案是否定的，就应减少流程控制或装饰性动效。
